# Fine Tuning

`neb_data_set_synth` stays the NEB curation layer. Its curated outputs are the
source of truth for the family-specific fine-tuning paths.

Primary entrypoints:

```bash
mlip-ft mace --curate-neb --inputs demo/fine_tuning/mace/0_raw_inputs/siv_rules.yml
./demo/fine_tuning/mace/2_train/run_fine_tuning.sh
mlip-neb --inputs demo/fine_tuning/mace/4_benchmark --report-benchmark
mlip-ft orb --curate-neb --inputs demo/fine_tuning/orb/0_raw_inputs/siv_rules.yml
./demo/fine_tuning/orb/2_train/run_fine_tuning.sh
mlip-neb --inputs demo/fine_tuning/orb/4_benchmark --report-benchmark
mlip-ft petmad --curate-neb --inputs demo/fine_tuning/petmad/0_raw_inputs/siv_rules.yml
./demo/fine_tuning/petmad/2_train/run_fine_tuning.sh
mlip-neb --inputs demo/fine_tuning/petmad/4_benchmark --report-benchmark
```

The demo workflows now use one folder per family with numbered steps:

- `0_raw_inputs/` owns the rules and raw NEB bundle
- `1_curated_data/` receives the curated output
- `2_train/` runs the family trainer
- `3_results/` stores the training artifacts
- `4_benchmark/` compares the original model against the fine-tuned model on
  the raw NEB endpoints

ORB and PET-MAD both reuse the same curation entrypoint, but ORB implicitly
converts the curated extxyz files to ASE sqlite DBs before training starts.
The benchmark report is generated by the same `mlip-neb` command with
`--report-benchmark`.
